# Птичий двор — кандидат для production

Подготовлен 12.11.2026 из сохранённой версии лаборатории v44. Это комплект для серверного агента QuRa, не самостоятельный сервер экономики. Текущий прод не переключён.

## Что входит

- client/ — чистый клиент, графика, выбранные звуки, утверждённый микс; громкость по умолчанию 30%, равная прежнему уровню.
- server/replay-engine.mjs — автономный ESM-модуль Node.js 20+ с тем же детерминированным движком, checkpoint и валидацией баланса.
- server/balance-defaults.json — новая базовая ревизия параметров; integration/ — контракты и звуковой микс; licenses/ — атрибуция.
- release.json — хеши, протокол и условия активации; verify.mjs — проверка целостности и совпадения replay клиента/сервера на 3000 тиках; stage.mjs — подготовка файлов в чистой рабочей ветке QuRa без переключения маршрута.

Демо-оболочка, локальные GE/API, sound-lab и sound-mixer в клиенте отсутствуют. У интерфейса нет служебной панели, приписок об обновлении и ссылок на отчёты.

## Проверка и подготовка ветки

Из каталога пакета: `node verify.mjs`. Нужен Node.js 20+, зависимости не устанавливаются.

Создать отдельный чистый worktree/ветку от актуальной main QuRa. Выполнить `node /path/to/package/stage.mjs /absolute/path/to/QuRa/worktree`. Скрипт не работает в main, не перезаписывает существующий r4 и не меняет r3/маршрутизацию. Он только размещает кандидат в web/public/games/poultry/r4 и серверный replay-кандидат в integration/poultry/releases/poultry-v3-20261107.

## Обязательная совместимость

При чтении GitHub main QuRa 12.11.2026 файл web/public/games/poultry/r3/session-replay.js объявлял poultry-v1. Этот пакет объявляет poultry-v3-20261107, включая команду view и новую логику спавна/баланса. Текущий сервер в этой сессии не проверялся; совпадение протоколов не подтверждено. Простая замена r3 небезопасна и может приводить к расхождению replay/отказам начисления.

Серверному агенту необходимо:

1. Найти текущие backend-адаптеры, allowlist протоколов, список допустимых команд, replay worker и источник engine hash. Подключить новый модуль через существующий изолированный replay-процесс. Сам по себе файл в integration/ не включает поддержку.
2. Закрепить одинаковые ENGINE_PROTOCOL, engine hash и immutable balance snapshot на сервере и клиенте. Создать НОВУЮ ревизию баланса из balance-defaults.json; не подмешивать текущий старый snapshot, он перезапишет новые значения клиента. Проверить цены и политику наград по действующей серверной конфигурации, не импортировать отключённый reward-policy.json как разрешение начислений.
3. Новые сессии открывать на r4, активные r3 завершать старым движком и старым балансом. Для команд view проверить bounds 300–1600 × 300–1200 и последовательность; digest/seq, авторизация, CSRF и idempotency остаются обязательными.
4. Проверить bootstrap → start → batch → restore → settle; покупки/quote, повтор settle и сундуков без повторных списаний/начислений; серверную защиту чужих сессий. Не начислять реальные награды по клиентским итогам. Проверить долгий replay до обоих боссов и бонусной волны, паузы, восстановление, мобильное и широкое окно.
5. Проверить браузеры 390×844, 360×740 и desktop: меню, звук 0/30/100%, движение, эволюции, оба босса, выход, результаты. Радио проверяется отдельно; использует внешний поток и не является офлайн-ресурсом.

Новые активные игровые сессии и баланс переключать только после этих проверок. В пакете activationReady=false до проверки действующего backend и утверждения точного QuRa main SHA.

## Выкатка и откат

По актуальным CLAUDE.md и docs/DEPLOY_COMMANDS.md QuRa: отдельная ветка → проверки → PR → merge; production только из чистой main. Не выполнять копирование поверх /opt/QuRa в обход Git и supervisor.

На сервере сначала `venv/bin/python scripts/manual_deploy.py --sha FULL_MAIN_SHA --dry-run`, затем штатный выкат с тем же проверенным SHA по текущей политике CI/локальных проверок. Supervisor держит /opt/QuRa/.deploy.lock, делает backup, staging build, restart только qura-* и smoke. Следовать актуальной серверной документации; не выполнять отдельные pull/build/restart вне lock. Подключить browser-check для полноценной UI-приёмки.

Откат новых сессий — возврат клиентского маршрута и серверного баланса/версии на r3 через Git и штатный supervisor. Не удалять r4 replay, пока остались активные сессии r4; не перезаписывать snapshots текущих сессий. При миграциях использовать предусмотренный supervisor rollback с проверенным backup.

В этом чате не выполнялись изменения production, PR в QuRa, серверные рестарты, миграции или реальные транзакции. Они не считаются выполненными проверками.
