## Работа в QuRa

1. Прочитать актуальные `AGENTS.md`, `CLAUDE.md`, `docs/DEPLOY_COMMANDS.md` и правила хоста. Создать чистую отдельную рабочую ветку от актуальной `main`. Не использовать старый локальный checkout как источник актуального backend.
2. Прочитать `releases/2026-11-12/README.md`: там перечислены контракты, smoke, порядок переключения и откат.
3. Из каталога комплекта выполнить `node stage.mjs /absolute/path/to/QuRa/worktree`. Это размещает клиент в `web/public/games/poultry/r4` и matching replay-кандидат в `integration/poultry/releases/poultry-v3-20261107`. Скрипт не переключает маршрут, не поддерживает merge поверх существующего r4 и отказывается работать в main или грязном дереве. Если r4 уже существует, сначала изучить его, не удалять и не перезаписывать автоматически.
4. Подключить новый протокол к **реальному** backend: команды (включая `view`), версия движка/hash, replay worker, новая immutable ревизия баланса, выбор версии для новых сессий. Тестовый `preview-api` не переносить. Активные старые сессии должны использовать старые движок и snapshot до завершения.
5. Проверить start → batch → restore → settle, pause/resume, quote/purchase, повторы/конкурентность, сундуки и права доступа; долгий replay через обоих боссов и бонусную волну. Не выдавать награды по клиентским итогам. Проверить UI на телефоне и desktop, звук 0/30/100% и радио.
6. Diff → необходимые проверки → commit/push рабочей ветки → PR → merge. Деплой только точного принятого QuRa main SHA, из чистого дерева, штатным `manual_deploy.py` под deploy lock. Сам комплект не меняет API, кошельки, миграции или живой маршрут.
7. В отчёте указать QuRa PR/main SHA, протокол и engine hash, balance revision, результаты smoke и путь отката. Без проверки совместимости `activationReady=false` сохраняется.
